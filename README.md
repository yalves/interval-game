# Musicle 🎹

A daily ear-training game in the style of Wordle: every day you hear two piano notes and have **4 guesses** to name the interval between them.

## How it works

- **Three daily puzzles**: *Intervals* (two notes, name the distance between them), *Chords* (name the chord type) and *Harmony* (hear the I chord of a key, then another diatonic chord, and name its degree, II–VII; minor keys use the natural minor scale). Each is picked by a seeded random generator from the date, so everyone gets the same puzzle on the same day, and the answer never repeats on consecutive days. Puzzle #1 is 2026-10-28; a new one starts at local midnight. `tests/fixtures/daily-intervals.json` locks the published interval puzzles so they can't change by accident.
- **Feedback**: 🟩 correct · 🟨 wrong but same family · ⬛ wrong. Interval families are perfect/imperfect consonances and dissonances; chords are grouped by their third; degrees by harmonic function (tonic III/VI, subdominant II/IV, dominant V/VII).
- **Hints** after each miss: another way to listen (together / one note at a time / bass line), then the size (number of chord notes, or for Harmony whether the key is major or minor, then the chord quality), then the family.
- **Hard mode**: 3 listens, no hints; shared results get a `*`.
- **After the game**: the answer is shown on a keyboard with correct note spelling (A♭→G for a major 7th, not G♯→G), with a well-known song for the interval, and the answer buttons replay each option from the same starting note.
- **Practice**: unlimited puzzles; choose which intervals (including compound ones up to the double octave) or chords to include, the direction and the playback. It focuses on what you miss most and lists your weak spots and usual confusions.
- **Archive**: past daily puzzles can be played from the statistics screen (they don't count toward streaks).
- **Sound**: recorded piano and nylon guitar (see [CREDITS.md](CREDITS.md)), with a synthesized piano as fallback; volume control; plays even with the iPhone ring/silent switch off.
- **Accessibility**: high-contrast colors for color vision deficiency, keyboard shortcuts (Space, 1–9/0, arrows, Enter), respects the system's reduced-motion setting.
- **Languages**: English (default) and Brazilian Portuguese, picked from the flag menu. All UI text lives in `js/i18n.js`; to add a language, add it to `STRINGS` and `LANGUAGES` (and its flag to `js/flags.js`). A test checks that every language has the same keys.
- **Installable and offline**: web app manifest and a service worker (`sw.js`) that caches everything after the first visit.
- **Progress transfer**: settings → copy a code and import it on another device. Everything is stored in `localStorage` under `musicle:`.
- **Link previews**: Open Graph tags and `images/og.png`. Icons and the preview image are generated by `node scripts/render-images.cjs`.

## Running locally

It's a static site with no build step. ES modules require a web server (opening `index.html` via `file://` won't work):

```sh
npm start        # python3 -m http.server 8000 → http://localhost:8000
npm test         # tests for the puzzle logic (Node 18+)
```

## Structure

```
index.html
css/style.css
js/games.js      # pure logic: daily/random puzzles, scoring, hints, note spelling, share text
js/practice.js   # practice stats: weak spots and adaptive weights
js/audio.js      # sampled instruments, synth fallback, iOS audio session
js/i18n.js       # UI text for each language
js/flags.js      # SVG flags for the language menu
js/storage.js    # localStorage helpers and progress export/import
js/main.js       # UI
sw.js            # service worker (offline)
samples/         # instrument recordings (CC BY 3.0, see CREDITS.md)
images/          # icons and link-preview image (scripts/render-images.cjs)
tests/           # node:test tests
```

Locally the service worker is off (so edits show up right away); add `?sw` to the URL to test it.

## Deploying

The site is served by GitHub Pages from the `gh-pages` branch: https://yalves.github.io/musicle/

`.github/workflows/pages.yml` runs the tests on every push to the default branch and, if they pass, updates `gh-pages`, so the live site follows the default branch automatically.
